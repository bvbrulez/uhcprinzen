# UHC Prinzen

Statische Frontend-Anwendung für die Wesselbleker Prinzen, aufgebaut wie die
Referenzanwendung `balkonkraftwerk`. Die Seite benötigt keinen eigenen Server:
öffentliche Inhalte und die Mannschaftskasse werden direkt aus Supabase geladen.

## Lokal starten

Die Anwendung kann mit jedem statischen HTTP-Server gestartet werden, zum Beispiel:

```sh
python3 -m http.server 8080 --directory src
```

Danach ist die Seite unter <http://localhost:8080> erreichbar. Für die lokale
Ansicht ohne Supabase bleiben Platzhalter für Team und Spielplan sichtbar.

## Supabase einrichten

1. Projekt in Supabase anlegen.
2. In `src/supabase-config.js` die Projekt-URL und den **anon public key**
   eintragen. Der `service_role`-Key darf niemals in den Browser gelangen.
3. Im SQL-Editor das Datenmodell und die Zugriffsregeln anlegen:

   ```sql
   create table public.members (
     id bigint generated by default as identity primary key,
     name text not null,
     role text,
     active boolean not null default true
   );

   create table public.matches (
     id bigint generated by default as identity primary key,
     match_date date not null,
     opponent text not null,
     location text
   );

   create table public.transactions (
     id bigint generated by default as identity primary key,
     type text not null check (type in ('INCOME', 'EXPENSE')),
     description text not null,
     amount numeric(10, 2) not null check (amount > 0),
     transaction_date date not null,
     category text not null
   );

   alter table public.members enable row level security;
   alter table public.matches enable row level security;
   alter table public.transactions enable row level security;

   create policy "Public can read active members"
     on public.members for select to anon, authenticated using (active = true);
   create policy "Public can read matches"
     on public.matches for select to anon, authenticated using (true);
   create policy "Members can read transactions"
     on public.transactions for select to authenticated using (true);
   create policy "Members can add transactions"
     on public.transactions for insert to authenticated with check (true);
   ```

4. Unter **Authentication → Users** die berechtigten Mitglieder anlegen.
5. Die Seite über GitHub Pages veröffentlichen oder `src/` auf einen statischen
   Webserver deployen.

## Deployment

Die GitHub-Action veröffentlicht `src/` bei jedem Push auf `main` automatisch
als GitHub-Pages-Seite.
